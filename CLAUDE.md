# CLAUDE.md

Правила для Claude Code в репозитории `financial-systems`. Полная целевая архитектура — в `docs/target-design.md` (разделы 3, 7, 8 суммированы ниже). Проект переписывается с нуля, старый код (Django/React) не копируется и служит только справочником по функциональности.

## Стек

Next.js (App Router) + TypeScript, src/-директория, Tailwind CSS 4, shadcn/ui, pnpm. На этапе прототипа (шаги 01–08) данных и бэкенда нет — всё на моках из `src/mocks`. БД (PostgreSQL + Drizzle), Better Auth, S3, ledger — следующий этап.

## Язык и тексты

- Код и база данных — только английский.
- Тексты интерфейса — только русские, только из словаря `src/messages/ru.ts`. Не дублировать подписи по компонентам: одно понятие — одна запись в словаре.
- Имена — по глоссарию (раздел 4 `target-design.md`). Никакого транслита и сокращений (`sebes`, `prf`, `calc_1` и т. п.). Одно понятие — одно слово везде: если в UI «Поступление», то в коде всегда `IncomingPayment`.
- TypeScript: `camelCase` для переменных и функций, `PascalCase` для типов и компонентов, `SCREAMING_SNAKE_CASE` для констант, `kebab-case.ts` для файлов. Функции называются глаголом (`calculateClientCharge`), булевы как в БД (`isConfirmed`, `canClientEditPayment`).
- Структура предметной области — по доменам, не по слоям: `src/modules/<domain>/{schema,queries,actions,pricing,ui}`.

## Деньги

- Тип денег в данных — всегда `string`. В коде **никогда** `number` для денежных величин.
- Расчёты — только через `decimal.js`.
- Вывод суммы на экран — только через компонент `Money` (моноширинные цифры, выравнивание вправо, код валюты после суммы).

## components/ui и components/custom

- `src/components/ui` — стандартный shadcn, **руками не редактируется никогда**. Любое ручное изменение должно падать на `pnpm check:ui`.
- Новый shadcn-компонент добавляется только командой `pnpm dlx shadcn@latest add <component>` и дописывается в `scripts/ui-components.json` (этот список использует `check:ui`).
- `src/components/custom` — всё своё, собирается только из `ui`-компонентов и Tailwind-утилит для раскладки (`flex`, `grid`, `gap`, ширины, отступы). Цвета, скругления и тени ui-компонентов через `className` не переопределяются — только их `variant` и `size`.
- Тема — стандартная shadcn (`neutral`), светлая и тёмная. Свои цвета и правки `globals.css` сверх того, что сгенерировал shadcn, не добавляются.
- Один файл — один компонент, имя `kebab-case`, экспорт `PascalCase`.

## Роли и URL

- Роли: `client` и `manager`. Слова `admin` и `staff` в коде не используются.
- Два пространства маршрутов: `/client/*` и `/manager/*`, каждое со своим `layout.tsx`, который первым делом проверяет доступ (`requireClient()` / `requireManager()`). Менеджер на `/client/...` и клиент на `/manager/...` получают 404, а не редирект.
- Сегменты URL — по-английски, `kebab-case`, множественное число, совпадают с именами сущностей в коде (`payment-orders` ↔ `paymentOrders` ↔ `payment_orders`).
- Создание сущности — `/new`, карточка — `/[id]`. Отдельных `/edit` нет, редактирование — в карточке.
- Фильтры, сортировка, страница таблицы — в query-параметрах (ссылку на отфильтрованный список можно переслать).

## Три шаблона страниц — других не придумывать

1. **Список**: `page-header` (заголовок + одна основная кнопка) → строка фильтров → `data-table`.
2. **Карточка**: заголовок с номером/статусом/кнопками действий → две колонки (слева `description-list` и документы, справа суммы/расчёт/история статусов).
3. **Форма**: одна колонка ~720px, разделы `form-section`, подписи над полями, ошибки под полем, кнопки внизу справа.

## Принципы интерфейса

- Одна основная кнопка на экране (`variant="default"`), остальные `outline`/`ghost`. Опасные действия — только через `confirm-dialog`.
- В карточке показываются только допустимые переходы статуса из матрицы, остальные кнопки не рисуются вовсе.
- Цвет несёт смысл, а не украшает: интерфейс монохромный (`neutral`), `destructive` только для ошибок/опасных действий, статусы различаются подписью и вариантом `Badge`, без своих цветов.
- Даты в формате `09.10.2026`, время только где важно.
- Загрузка — `Skeleton` по форме контента, пустой список — `Empty` с действием, ошибка формы — у поля, ошибка страницы — `Alert`, успех — toast.
- Кнопки называются глаголом («Подать заявку», «Подтвердить поступление»).

## Перед завершением любой задачи

Прогнать `pnpm check` (lint + typecheck + check:ui). Все три должны проходить.
