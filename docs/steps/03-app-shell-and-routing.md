# Шаг 03. Разделы /client и /manager, имитация входа, каркас

## Контекст

Прочитай `CLAUDE.md` и разделы 7 и 8.2 в `docs/target-design.md`. Типы, тексты и слой данных на моках готовы (шаг 02). Теперь нужен каркас приложения, в который дальше встанут все экраны.

## Задача

### 1. Имитация входа (`/login`)

- Страница по образцу shadcn-блока `login` (скопируй блок в `src/components/custom/`): заголовок, поля «Логин» и «Пароль» и кнопка «Войти».
- На этапе прототипа под формой стоит список тестовых пользователей (`client.alfa`, `client.beta`, `manager.full`, `manager.payments`). Клик по пользователю ставит cookie `mock_user_id` и отправляет на `/`. Поля логина и пароля пока не работают, это видимый макет будущего входа.
- Выход (`/logout` или пункт меню) удаляет cookie и ведёт на `/login`.
- Пометка «Режим прототипа» в углу экрана входа, чтобы никто не принял это за настоящий вход.

### 2. Маршрутизация

- `/` редиректит: нет пользователя → `/login`, клиент → `/client`, менеджер → `/manager`.
- `middleware.ts` пропускает без пользователя только `/login`.
- `app/client/layout.tsx` вызывает `requireClient()`, `app/manager/layout.tsx` вызывает `requireManager()`. Функции лежат в `src/modules/auth/guards.ts`. Не та роль → `notFound()` (404), а не редирект.
- Внутри `/manager` каждая страница раздела вызывает `requireManager('<section>')`. Если раздела нет в правах, ответ 404.
- Создай все маршруты из раздела 7 дизайн-документа. Пока каждая страница — пустая заготовка с правильным заголовком (`page-header` можно сделать временно простым, полноценный появится в шаге 04).
- `/account`: заглушка «Профиль» с блоками «Пароль» и «Двухфакторная аутентификация» (без логики).

### 3. Каркас (`src/components/custom/app-shell.tsx`)

По образцу shadcn-блока с sidebar (скопируй блок в `custom` и доработай там):

- **Меню слева** (shadcn `Sidebar`, сворачивается до иконок, на телефоне открывается как sheet):
  - Клиент: Обзор, Заявки, Контрагенты, Выписка.
  - Менеджер: Обзор, Заявки, Поступления, Переводы, Исходящие платежи, Балансы, Журнал проводок, группа «Настройки» (Организации, Плательщики, Схемы исполнения, Счета, Поставщики, Пользователи).
  - Пункты, на которые у менеджера нет прав, не показываются.
  - У пунктов «Заявки» и «Поступления» счётчик `SidebarMenuBadge`: сколько элементов ждёт действия текущего пользователя. Для клиента это заявки в статусах `sent_to_bank`, `awaiting_closing_documents`, `needs_correction`. Для менеджера — `submitted`, `in_review`, `closing_documents_review`, `correction_review` и неподтверждённые поступления. Счётчики берутся из `queries`.
- **Сверху:** хлебные крошки (shadcn `Breadcrumb`), справа меню профиля (`DropdownMenu` + `Avatar`): имя, роль, организация клиента, «Профиль», переключатель темы (светлая / тёмная / системная), «Выйти».
- **Контент:** отступы и максимальная ширина по разделу 8.2. Шапка не содержит ничего, кроме крошек и профиля.
- Название продукта в шапке меню: «Financial Systems».
- Конфигурация меню описывается данными (`src/modules/navigation/config.ts`), а не разметкой. Права и счётчики накладываются на неё.

### 4. Состояния

- `loading.tsx` на уровне `client` и `manager` со скелетоном каркаса контента.
- `not-found.tsx` и `error.tsx` в стиле shadcn `Empty` с кнопкой «На главную».

## Не делать

- Не наполнять страницы содержимым, кроме заголовков.
- Не трогать `src/components/ui`.

## Как проверить

- Вход как `client.alfa`: видно клиентское меню, адрес `/client`. Ручной переход на `/manager` даёт 404.
- Вход как `manager.payments`: в меню только Обзор, Поступления, Переводы. Ручной переход на `/manager/payment-orders` даёт 404.
- Вход как `manager.full`: видно всё меню, счётчики показывают числа из моков.
- Меню сворачивается, на ширине 375 px открывается шторкой, тёмная тема переключается, выход работает.
- `pnpm check` проходит.
